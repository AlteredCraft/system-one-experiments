What can a model do when it can't write?

System One models don't generate text. They answer a typed question about some state with a probability for every answer, in milliseconds. These experiments test where that's enough to stand in for a parser, a grader, a release manager, or the choice of which model to call.

EXP-04 · model-router · Node Live · 3 models

Which model should this sub-agent run on?

An agent harness asks one Score question about a sub-agent's task, then takes the cheapest model whose chance of being too weak is acceptable. The orchestrator spends no tokens deciding.

One Jev call over the text of a sub-agent task chooses a model tier well enough to move a large share of work off the most capable model, while rarely sending a task to a model too weak for it.

EXP-02 · godot-jev · Godot 4.7 Live · 2 models

The Sunken Crypt

A dungeon crawl whose parser understands whatever you type but can only choose moves the author wrote. Each turn, the possible moves become one Choice, plus "none of these".

Players type naturally with few dead ends, the game stays fully authored, and it's fast enough to feel like a parser, not a chat.

03

Protocol

Every experiment is built the same way. It keeps the model replaceable and the tests honest.

  1. A decider port

    Code asks decide(state, questions). One adapter calls Jev; a scripted one drives the tests. No unit test calls the network.

  2. Policy in code

    Thresholds, arithmetic, dates and counting stay in ordinary code. A policy change is a code change, not a prompt rewrite.

  3. Ask only what's open

    Deterministic rules go first. The model answers only what they leave undecided.

  4. Confidence decides the path

    Act, ask or escalate by how sure the model is, with the bar set by the cost of being wrong.

  5. Fail safe

    If the model is unreachable, fall back to what the system did before it had one.

05

Read before trusting

Limits that apply to every experiment here.

  • Jev takes text only and reads instructions literally.
  • It can't count or compare dates. That's why arithmetic and thresholds live in code.
  • Text inside the state can argue for an answer: a learner, a commit author, a player or an orchestrating model can write "this is trivial".
  • Where the state comes from someone with a reason to game it, keep the stakes of any automatic action low, or keep a human in the loop.
